# 业务提效评估方案

本文档用于把技术评估转换为可验证的业务影响指标。当前项目已有 RAG、IFC 解析、合规判定等技术指标，但在没有人工基线前，不应直接写“提效 X%”。

## 评估结论口径

当前可确认：

- 系统可自动完成规范召回、条文页码定位、IFC 字段提取、信息不足判断和审查草稿整理。
- 已有离线评估覆盖 RAG 召回、IFC 事实解析、合规判定、多轮上下文和回答质量。
- 业务提效百分比仍需通过人工基线对照实验获得。

对外描述推荐写法：

> 构建 BIM 消防合规审查 Agent，将规范问答、IFC 模型事实查询、消防合规审查拆分为独立工作流；建立分层评估体系，覆盖 RAG 召回、IFC 事实解析、合规判定和多轮上下文，支持标准号、条文号、PDF 物理页、原文片段和信息不足提示的可追溯输出。

完成计时评估后可替换为：

> 在 N 个典型消防审查任务中，将规范定位、IFC 字段提取和审查草稿整理的平均耗时从人工 X 分钟降至系统辅助 Y 分钟，整体初审准备耗时下降 Z%，同时保持安全关键漏检率 0%。

## 评估任务

| task_id | 任务 | 人工完成定义 | 系统辅助完成定义 | 主要指标 |
| --- | --- | --- | --- | --- |
| T01 | 查找疏散出口门净宽条文 | 找到标准、条文号、页码、原文 | 提问后核对引用来源 | 规范定位耗时 |
| T02 | 查找地下汽车库疏散距离 | 找到自动灭火系统条件下的距离限制 | 提问后核对引用来源 | 规范定位耗时 |
| T03 | 判断门宽是否信息充分 | 人工确认门用途、建筑类型、门宽字段 | 系统输出 PASS/FAIL/信息不足和缺失字段 | 初审判断耗时 |
| T04 | 从 IFC 提取楼层/门/楼梯/高度 | 打开模型或查看明细后手工记录 | 上传 IFC 后读取模型事实摘要 | 模型事实提取耗时 |
| T05 | 生成可复核审查草稿 | 汇总问题、依据、结论和缺失字段 | 导出报告或审查档案后人工核对 | 草稿整理耗时 |

## 记录字段

记录到 CSV 后可运行 `scripts/evaluate_productivity_benchmark.py` 汇总。

| 字段 | 说明 |
| --- | --- |
| task_id | 对应上面的任务编号 |
| participant_role | 参与者角色，例如 PM、BIM 设计师、消防审查熟手 |
| manual_seconds | 人工完成耗时，单位秒 |
| assisted_seconds | 系统辅助完成耗时，单位秒 |
| manual_success | 人工结果是否通过核验，`true/false` |
| assisted_success | 系统辅助结果是否通过核验，`true/false` |
| notes | 失败原因、卡点或观察 |

## 指标公式

- 单任务提效：`(manual_seconds - assisted_seconds) / manual_seconds`
- 总体提效：`1 - sum(assisted_seconds) / sum(manual_seconds)`
- 成功率：`success_count / task_count`
- 推荐同时报告 P50/P90 耗时，避免只用平均值掩盖长尾问题。

## 可信边界

- 不把技术评估指标直接换算成业务提效。
- 不用单个演示样例代表真实试点效果。
- 如果参与者不是专业审查人员，应在报告中标注“模拟任务基线”。
- 若系统答案需要人工二次核验，辅助耗时必须包含核验时间。
