# IFC 解析与消防规范 RAG 的处理链路

## 定位

IFC 模块不是新的规范问答系统，而是消防合规检查系统的“项目事实输入层”。

- IFC 解析负责回答：模型里有什么、尺寸是多少、属于哪个楼层、可能是什么消防审查对象。
- 规范 RAG 负责回答：对应规范条文是什么、页码在哪里、原文如何表述。
- 合规判断负责回答：IFC 事实是否满足召回条文；证据不足时提示人工复核。

## 当前解析方法

当前使用 IfcOpenShell 读取 IFC 文件，按 IFC 实体类型和属性集抽取消防审查相关字段。

已抽取对象：

- `IfcProject`、`IfcSite`、`IfcBuilding`：项目、场地、建筑基本信息。
- `IfcBuildingStorey`：楼层名称、高程，用于推算建筑高度和楼层数量。
- `IfcSpace`：空间名称、楼层归属、面积属性，识别疑似汽车库、中庭等空间。
- `IfcDoor`：门名称、楼层归属、宽度、高度、防火性能、是否外门、是否疑似疏散出口。
- `IfcStair`、`IfcRamp`、`IfcTransportElement`、`IfcFlowTerminal` 等：识别楼梯、坡道、电梯、消防设施相关构件。

字段来源：

- IFC 原生属性：如 `OverallWidth`、`OverallHeight`、`Elevation`。
- 属性集：如 `FireRating`、`IsExternal`、`NetFloorArea`、`GrossFloorArea`。
- 名称和类型标签：用于识别疑似中庭、汽车库、疏散出口、消防设施等场景。

## 处理链路

1. IFC 上传
   用户上传 `.ifc` 文件，系统保存临时副本用于解析。

2. IFC 解析
   IfcOpenShell 打开模型，按实体类型读取楼层、空间、门、楼梯、消防设施等对象。

3. 字段归一
   将不同属性来源统一成可审查字段，例如门宽、楼层高程、空间面积、防火性能、外门属性。

4. 场景识别
   根据 IFC 类型、属性集和对象命名识别疑似消防审查场景。这里不直接下合规结论。

5. 生成审查问题
   将结构化事实转成自然语言问题，例如：
   “基于 IFC 解析：某楼层某门宽度约 0.78m，可能作为疏散出口门使用。请检索规范判断是否满足最低要求。”

6. 规范 RAG 检索
   审查问题进入现有 BM25 + FAISS + rerank 检索链路，返回标准号、条文号、PDF 物理页和原文片段。

7. LLM 合规判断
   DeepSeek 只基于 IFC 事实和召回原文生成结论，并给出证据置信度、模型判断置信度和人工复核提示。

## 与消防合规检查系统的逻辑关系

当前系统分为三层：

- 事实层：IFC 解析，提取项目事实。
- 规范层：RAG 知识库，召回可追溯条文。
- 判断层：把项目事实与规范条文对比，输出可审查结论。

因此，IFC 模块的价值不是“让模型自己猜规范”，而是减少用户手动输入项目条件，把 BIM 模型中的尺寸、楼层、空间和构件信息转化为可被 RAG 审查的问题。

## 当前边界

- 目前不做完整疏散路径几何计算。
- 目前不自动判断防火分区边界是否闭合。
- 目前不自动计算房间到最近安全出口的真实行走距离。
- 目前不把命名关键词当成最终结论，只作为候选场景提示。
- 若 IFC 模型缺少宽度、面积、防火等级等属性，系统只能提示字段缺失，不能强行判断合规。

## 下一步

1. 增加 IFC 字段质量评分：哪些字段可审查，哪些字段缺失。
2. 增加门、房间、楼梯、出口之间的空间拓扑关系。
3. 增加疏散距离几何计算。
4. 将 IFC 解析结果和 RAG 引用结果合并成一份合规检查报告。
5. 建立 IFC 测试样例集，验证不同建模习惯下字段能否稳定抽取。
