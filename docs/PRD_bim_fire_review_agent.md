# PRD：建筑消防合规智能审查助手

## Overview

### Problem Statement

建筑消防审查工程师在核对规范时，通常需要跨多份标准检索条文、比对项目条件、核对数值，再整理成可复核结论。现有工作流存在三类问题：

1. 规范检索依赖人工经验和关键词，容易遗漏当前通用规范、专项规范与旧版设计规范之间的适用关系。
2. BIM/IFC 模型中已经包含楼层、门宽、空间、楼梯等事实，但审查时仍需要人工提取并转写成问题，效率和一致性不足。
3. 大模型问答容易把“相关但不适用”的条文当成答案，缺少引用来源、置信度解释和人工复核边界，不能直接用于严肃审查场景。

本项目已经具备可运行的两条主线：独立规范问答，以及 IFC 解析后的事实查询和消防合规审查。当前核心目标不是继续堆功能，而是把已有能力产品化，同时把召回、合规判定、多轮上下文和回答可信度做到可验证、可追责。

### Solution Summary

构建一个桌面工作台式建筑消防合规审查助手，包含两个并列主模块：

- **规范问答**：用户可以不依赖 IFC，直接输入消防规范问题；系统返回前置结论、规范依据、条文号、PDF 物理页、原文片段、证据置信度和模型判断置信度。
- **BIM 模型审查**：用户上传 IFC 模型后，系统先解析模型事实；用户可以独立查询模型内容，也可以补充项目条件后进行消防合规审查，输出 `PASS / FAIL / INSUFFICIENT_INFORMATION` 三类结论。

两条主线共享知识库、会话、历史、证据展示和评估机制，但职责必须分离：

- IFC 解析负责“模型里有什么”。
- 规范 RAG 负责“哪份标准、哪条条文怎么说”。
- 合规判断负责“模型事实与项目条件是否满足召回条文”。

### Target Users

- **消防审查工程师**：需要快速定位规范依据并判断项目是否合规。
- **BIM 设计师与建筑设计师**：需要把 IFC 模型事实转化为可检查问题。
- **初级审查人员**：需要可核查回答，降低漏检风险。
- **原型验证与产品展示场景**：需要能够展示完整产品逻辑、证据链和边界处理。

## Goals & Success Metrics

### Goals

1. 让规范问答做到“先给结论、再给依据、证据不足不编造”。
2. 让 IFC 解析、模型事实查询和消防合规审查成为清晰独立的子工作流。
3. 让多轮对话能够识别追问、对比、证据追溯和话题切换，但不硬编码特定问题。
4. 让系统在关键数值、表格字段和合规判定上减少 LLM 不确定导致的偶发错误。
5. 让评估体系覆盖解析、检索、合规判定、多轮行为、最终回答可信度，作为产品验收依据。

- 不替代正式消防审查、审图机构或主管部门的最终认定。
- 不做真实疏散路径几何计算、火灾蔓延模拟或性能化消防分析。
- 不在当前版本收录完整国家、行业和地方标准库。
- 不做多用户、权限、登录和云端协作。
- 不在当前版本生成正式报审报告。
- 不在用户界面展示测试集、Hit@1、迭代记录等内部工程信息。

## Scope

### In Scope

- 独立规范问答工作流。
- 当前 5 份规范知识库：
  - GB 50016-2014 建筑设计防火规范
  - GB 50067-2014 汽车库、修车库、停车场设计防火规范
  - GB 55036-2022 消防设施通用规范
  - GB 55037-2022 建筑防火通用规范
  - GB 55038-2025 住宅项目规范官方条文摘录
- IFC / IFCXML 上传与本地解析。
- IFC 项目、楼层、空间、门、楼梯、坡道、电梯、消防设施相关字段提取。
- 模型事实独立问答。
- 项目条件自由文本输入。
- IFC 消防合规审查，输出 `PASS / FAIL / INSUFFICIENT_INFORMATION`。
- 多轮上下文路由，覆盖新话题、追问、对比、证据追溯、纠错。
- 引用来源、证据置信度、模型置信度、缺失字段和人工复核提示。
- 多会话本地保存、查询历史和系统状态。
- 内部评估框架与回归入口，不进入用户界面。

### Out of Scope

- 登录、注册、多用户权限和云端账号体系。
- 服务端多用户会话持久化。
- 真实疏散路径几何计算、防火分区边界闭合检测、火灾模拟。
- 完整国家、行业、地方标准库。
- 地方审图口径与正式报审文件生成。
- 自动生成盖章或可用于申报的合规报告。
- 用户自定义模型编辑或修改 IFC 文件。

### Future Considerations

- **确定性数值规则引擎（基础版已实现）**：面积、距离、净宽等可计算比较已从 LLM 算术中分离为通用复核层，后续继续扩展数值来源抽取和结构化表格字段。
- **显式工具调用层**：把 IFC 模型查询从“摘要直接交给 LLM”升级为记录工具名、参数和执行结果的 Tool Calling 层。
- **服务端会话持久化**：支持跨设备、多项目和多成员协作。
- **正式合规报告**：把审查过程、结论、证据和缺失字段导出为可交付文档。
- **实时流式输出**：将停止生成升级为 SSE 或 WebSocket 的逐字流式生成。
- **语义重排 A/B**：对比本地重排和 SiliconFlow API reranker 的准确率、成本与稳定性。
- **知识库持续扩展**：补充更多规范、地方口径和标准关系维护机制。

## Solution Design

### Functional Requirements

#### 规范问答

- FR-1：用户可直接输入自由文本规范问题，系统返回前置结论、依据、标准号、条文号、PDF 物理页和原文片段。
- FR-2：当召回证据不足或适用条件不明确时，系统必须拒绝编造答案，并列出缺失字段。
- FR-3：支持知识库范围选择，包括自动识别、全部规范和指定标准。
- FR-4：用户可调整引用依据数量，范围为 3 至 10 条；页面展示的引用条数应与请求结果一致，冲突时给出明确提示。
- FR-5：回答生成期间提供“停止生成”入口；停止后本轮不写入对话记录。
- FR-6：多轮上下文路由至少支持 `new_topic / follow_up / comparison / evidence_request / correction` 五类判断，不能按测试题目或具体检查项硬编码。
- FR-7：追问继承用户明确提到的建筑对象、条件和检查项，但检索补全问题不得携带上一轮答案、数值或计算路径。
- FR-8：证据追溯问题应按主题匹配历史问题与历史证据，不能被最近无关话题污染。
- FR-9：追问回答应聚焦本轮新条件或差异点，不重复复述上一轮完整规则。
- FR-10：表格 OCR 存在列错位、数值缺失或行列不完整时，系统不得猜测列映射，应降级置信度或拒绝给出具体数值。
- FR-11：多规范冲突时按“现行通用规范 > 专项规范 > 旧版设计规范”的注册优先级组织回答，并提示需复核的关系。
- FR-12：置信度判定依据存在但默认折叠，不主动弹出；折叠区字号与正文一致。

#### BIM 模型审查

- FR-13：支持上传 `.ifc` 和 `.ifcxml` 文件，文件上限 200MB，解析失败时给出明确错误。
- FR-14：使用 IfcOpenShell 本地解析项目、场地、建筑、楼层、空间、门、窗、楼梯、坡道、电梯和消防设施相关对象。
- FR-15：统一提取门宽、门高、楼层高程、空间面积、防火性能、外门属性、疑似疏散出口等可审查字段。
- FR-16：输出字段质量摘要，明确“可用、缺失、需要人工确认”三类状态。
- FR-17：建筑用途识别只作为低置信度提示，不作为最终合规结论依据。
- FR-18：模型事实查询独立于规范 RAG，只能基于 IFC 中可读取或可计算的事实回答。
- FR-19：用户可通过自由文本补充项目条件，例如建筑类型、耐火等级、是否设置自动灭火系统、门的实际用途等。
- FR-20：合规审查必须同时使用 IFC 事实、用户项目条件和召回规范原文，输出 `PASS / FAIL / INSUFFICIENT_INFORMATION`。
- FR-21：`FAIL` 结论必须展示关键风险和判断过程；安全关键漏检不得出现。
- FR-22：系统可提供建议复核项，但建议项只是入口，用户必须可以自由输入任何审查问题。
- FR-23：IFC 解析与合规审查结果应绑定当前会话，切换模块和刷新页面后可以恢复。

#### 会话与历史

- FR-24：支持新建、切换、重命名和删除多个会话。
- FR-25：会话保存规范问答轮次、项目条件、IFC 文件信息、解析结果、模型查询记录和合规审查记录。
- FR-26：本地保存最近 50 个会话；旧单条对话记录迁移为第一个历史会话。
- FR-27：历史问答合并到左侧导航栏，与现有深色导航风格一致，不单独占用主内容区。
- FR-28：左侧导航固定，顶部功能栏固定，下方对话区独立滚动。

#### 知识库与系统状态

- FR-29：规范库页面展示当前已收录标准、标准号、知识片段数量和状态。
- FR-30：系统状态页面只展示服务、知识库、DeepSeek 和语义重排可用性。
- FR-31：用户界面不得展示测试集数量、Hit@1、迭代记录、内部评估指标或 UI 编辑控制。

### User Experience

整体采用 Stitch 桌面工作台风格：

1. 左侧深色主导航固定，包含规范问答、BIM 模型审查、规范库、查询历史、系统状态；问答和 BIM 模块下方内嵌历史会话列表。
2. 顶部固定功能栏显示当前模块名称和专家模式开关。
3. 主工作区按模块完整铺满，不采用小框或嵌套折叠导致遮挡。
4. 规范问答页面自上而下为工具栏、对话区、输入区；对话区可滚动，输入区固定在底部。
5. BIM 模型审查页面先展示模型来源、模型事实摘要、项目条件补充，再通过完整 Tab 切换“模型概览、模型内容查询、消防合规审查、解析字段”。
6. 回答卡片结构为：提问、直接结论、依据、置信度、缺失字段、置信度与复核说明、查看引用来源。

### Edge Cases

| Scenario | Expected Behavior |
|----------|------------------|
| 用户问“这个建筑合规吗”但未上传 IFC 或未描述条件 | 返回 `INSUFFICIENT_INFORMATION`，列出缺失的项目条件 |
| IFC 中门宽字段为 `null` | 不得猜测门宽，返回信息不足并提示门宽缺失 |
| 用户问“回到汽车库，刚才的 60m 来自哪一条” | 识别为证据追溯，匹配汽车库历史主题，不被最近无关话题污染 |
| 用户问“那如果是医疗建筑呢” | 继承“疏散楼梯/疏散宽度”检查项，替换建筑类型后重新检索 |
| 用户从汽车库切换为疏散出口门净宽问题 | 识别为新话题，不继承汽车库证据 |
| 表 5.5.18 或表 7.4.7 行列 OCR 损坏 | 拒绝猜测列映射，返回低置信度或需要人工确认 |
| 多份规范给出不同数值 | 按规范注册优先级展示最终依据，并列出冲突和复核提示 |
| 用户选择引用 10 条但实际只有 8 条有效依据 | 页面条数应等于返回结果，并说明差异原因，不静默冲突 |
| 生成过程中点击停止 | 中断请求，显示“已停止生成，本轮未写入对话” |
| 切换会话后重新回到 BIM 模块 | 恢复该会话绑定的 IFC 摘要、项目条件和审查记录 |

## Technical Considerations

### Constraints

- 后端为 FastAPI，前端为 React/Vite，推荐使用项目本地 Python 虚拟环境。
- DeepSeek 负责上下文路由、规范回答、模型事实回答和合规结论生成，`temperature=0`。
- IFC 解析使用 IfcOpenShell，本地执行，不上传第三方云端。
- 检索使用 BM25 + FAISS（`BAAI/bge-m3`）+ 本地重排；SiliconFlow API reranker 已封装但默认不启用，需要 A/B 评估。
- 多轮上下文路由必须使用通用意图和指代判断，不允许把测试场景或固定检查项写入线上规则。
- 表格可靠性门控优先于回答完整性；宁可返回信息不足，也不能给出列映射错误的数值。
- 知识库当前包含 5 份规范、2594 个可检索片段；GB 55038-2025 为官方条文摘录，不能承诺覆盖摘录外内容。

### Integration Points

- `/api/health`：系统状态。
- `/api/library`：知识库概览。
- `/api/qa`：规范问答，接收问题、范围、引用数量、历史上下文和重排开关。
- `/api/ifc/parse`：IFC 上传与解析。
- `/api/ifc/model-question`：模型事实问答。
- `/api/ifc/compliance-question`：IFC 消防合规审查。
- DeepSeek API：意图路由与回答生成。
- SiliconFlow API：Embedding 与可选语义重排。
- IfcOpenShell：IFC 文件解析。

### Data Requirements

- 规范知识以结构化 chunk 和向量索引保存，包含标准号、条文号、PDF 物理页、原文片段和表格索引。
- 规范关系保存在 `data/policy/`，包含标准注册表、路由规则和废止条文 seed。
- 会话和查询历史当前保存在浏览器 `localStorage`；后续需要升级为服务端 SQLite/JSON 持久化。
- IFC 文件解析后只保留结构化摘要和临时文件，不把原始文件当作知识库长期资产。
- 当前已具备基础 API 遥测，记录 HTTP 请求、失败、耗时、LLM 调用和 token；后续应补充轮次 ID、用户任务 ID、成本估算和可导出的观测报表。

### Business Impact Measurement

- 业务提效不由技术指标直接换算，需按 `docs/business_efficiency_evaluation.md` 执行人工基线和系统辅助基线对照。
- 当前推荐 5 类任务：规范定位、IFC 字段提取、门宽信息充分性判断、疏散距离判断、审查草稿整理。
- 对外展示提效百分比前，必须记录人工耗时、系统辅助耗时、成功率和核验口径。

| 表格结构化索引 | 后端 | 部分完成 | 数值和表格字段召回不稳定 |

### Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| LLM 数值判断偶发错误 | Medium | High | 已使用通用确定性复核层校正可计算比较，继续加强数值来源验证 |
| 表格 OCR 列错位导致错误数值 | Medium | High | 表格可靠性门控、结构化表格重建、人工抽检 |
| 多轮上下文误判 | Medium | High | Context Router 通用意图判断、离线多轮回归、失败归因 |
| 规范版本更新或废止关系不全 | Medium | High | 维护标准注册表和废止 seed，人工复核新增规范 |
| IFC 建模习惯差异导致字段缺失 | High | Medium | 字段质量评分、缺失字段提示、用户自由文本补充 |
| 知识库覆盖不足被误当“可完整审查” | Medium | High | 明示知识库边界，未收录规范返回信息不足 |
| API 成本、延迟和失败 | Medium | Medium | 增加遥测、超时重试、可选流式输出 |
| 安全关键结论漏检 | Low | High | Safety False Negative Rate 必须为 0，FAIL 场景持续回归 |
